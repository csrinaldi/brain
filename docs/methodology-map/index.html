brain

A working method for building software with AI agents, and the tooling that keeps the method honest. It installs into your own repository from a pinned git tag: a knowledge base that outlives the session, a spec-driven change flow, git-native team memory, and gates that read the evidence a change leaves behind.

An agent writes code faster than a team can agree on what it should do, or verify what it did. brain closes that gap at both ends — work starts from an approved issue and a written spec, and lands only after checks that read what actually happened rather than what anyone reported.

Knowledge outlives the session

Decisions live in the repository as ADRs; team memory is content-addressed and committed to git. The next session — human or agent — starts with what the last one learned.

One shape for every change

Issue, proposal, spec, design, tasks, code, review, merge — with the artifacts on disk at each step. The same shape whether a person or an agent drives it.

Machines prepare decisions, humans take them

The gates enforce that the process happened, never that the work is good. Approving and merging stays a human keystroke, and the reviewer has no code path that reaches it.

v1.0.0 — controlled pilot. Intended for repositories its maintainer controls, not yet open adoption. This repository runs on brain itself, which is how the method gets tested before it ships. Everything below is drawn from that tree.
