## What changes

1. **Signature column.** The input gains an optional `updatedSince`, and the return shape gains `state` and `body` (rulings R4 and R10).
2. **Return column, first sentence.** `state:'open'` becomes `state:'open'|'closed'`, and `updatedSince` is described.
3. **New sentences about `state` and `body`**, inserted after the `assignees` sentence, including the `null`-versus-`''` rule for both fields (ruling R12).
4. **GitHub-only normalization (1)** gains the cost of a closed read, which pages through closed PRs as well.
5. **Unchanged:** the pagination sentence (already true since #459, and verified against `github.mjs:458-465` and `gitlab.mjs:618-626`), the throw-on-failure divergence, and label unwrapping.

## Replacement row

| `issueList` | `({ project, state, assignee, updatedSince }) -> [{ number, title, labels, assignees, state, body }]` | `state:'open'\|'closed'`, `assignee:'me'\|'none'\|undefined`, `updatedSince`: an optional ISO-8601 time; when given, only issues updated at or after it are returned (GH `since=…&sort=updated&direction=asc`; GL `updated_after=…&order_by=updated_at&sort=asc`, both mapped inside the adapters), for incremental reads (issue #1257). Like `mrList`, `issueList` does not wrap its transport call — `runJson` throws on a non-zero exit or malformed JSON and neither provider catches it, so a transport failure REJECTS rather than yielding a null-shape (issue #362, M10 Phase 2 rank-4); unlike `mrList`, both call sites already absorb the throw (`tracker-board.mjs`'s `safeList` try/catch, `project-status.mjs`'s wrapping try/catch), so it is contained and load-bearing, not merely out of scope to fix. `assignees` added issue #533 / ADR-0029, with the same `string[]`-vs-`null` discipline as `issueView` — the list endpoint already carries the field on both providers, so "who is executing this" costs no extra round-trip. Additive `state` and `body` (issue #1257, mirroring #930 for `mrList`). `state` is `'open'\|'closed'\|null`: GH `r.state` when it is `'open'` or `'closed'`; GL `opened`→`open`, `closed`→`closed`, mapped inside `gitlab.mjs`; any other value, `''` included, or an absent field is `null` ("brain cannot see"), never guessed from the filter that was asked for. `body` is `string\|null`: GH `body`, GL `description`, mapped inside each adapter; a key that is ABSENT from the payload is `null` and is never turned into `''`; a key that is PRESENT with JSON `null` is `''`, an empty description, on both providers. The list endpoint already carries both fields on both providers, so neither costs an extra round-trip, and a caller that has the list needs no per-issue `issueView` to read bodies. Pagination: BOTH providers now paginate in full (issue #459) — GH via `gh api --paginate` at `per_page=100`, GL by walking pages of 100 and stopping on a short page; before that fix GH truncated at 100 and GL at 50, and a truncated list makes a derived graph assert there is no dependency where there is one. GitHub-only normalization: (1) GH's `/issues` endpoint returns both issues and PRs, so `github.mjs` filters out any entry carrying a `pull_request` field before mapping — with `state:'closed'` this means GitHub pages through closed PRs as well, which is the dominant cost of a full closed read on a PR-heavy repository (measured on this repository: about 16 s for all 592 issues with bodies, against about 2.5 s for the 136 open ones), and the reason a caller that needs closed issues repeatedly should read them in full once and then by `updatedSince`; (2) GH's `labels` field is an array of label objects, unwrapped to plain name strings via `.map(l => l.name)`, whereas GL's `labels` is already a flat string array requiring no unwrapping. |
