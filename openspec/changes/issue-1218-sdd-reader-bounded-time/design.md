# Design — sdd-reader-bounded-time (issue 1218)

## Technical approach

This design extends #1198's design (`issue-1198-sdd-artifact-reader/design.md`, D1–D14). It contradicts none of those decisions. One rationale is amended: D5's "the `run` seam ignores stderr anyway" stops being true, but D5's tri-state still never parses stderr. Stderr feeds only the reason text.

```
app.js (main thread; never tokenizes)       lib/render-budget.mjs (pure, effects injected)
expand ─▶ loading note ─▶ renderOffThread(text, {spawn, setTimer, clearTimer})
                               │ spawn() = new Worker('/lib/markdown-worker.mjs', {type:'module'})
                               ▼
              lib/markdown-worker.mjs ── {id,text} ─▶ markdownTree (pre-scan, then Lexer.lex)
                               ◀── {id, ok, tree} / {id, ok:false, error}
outcome: tree | timeout (1500 ms) | failed | unavailable | cancelled ─▶ token check ─▶ DOM
```

## Decisions

| # | Decision | Rejected | Why |
|---|---|---|---|
| D15 | **The pre-scan is pure and lives in `lib/markdown.mjs`.** It exports `prescan(body)`, which returns `[{from, to, marks, longestRun, degraded}]` by line index. `markdownTree` runs it on the body after the frontmatter. | A separate `lib/markdown-prescan.mjs` | It is about 40 lines and has one caller. A second module would add a lib file and a second door without isolating anything. |
| D16 | **What counts as an inline span.** A span is a maximal run of lines cut where marked starts a new inline run: (1) a blank line closes the span; (2) a list item (`/^\s*(?:[-+*]\|\d{1,9}[.)])(?:\s\|$)/`), a heading (`/^ {0,3}#{1,6}(?:\s\|$)/`) or a table row (`/^\s*\|/`) closes the span and opens a new one on that line; the continuation lines of a list item, indented or lazy, stay in the item's span (marked gives the item one text token, checked in the tests); (3) a block quote line is read through its prefix (up to three spaces, `>`, one optional space, repeated, in one linear pass): consecutive quote lines and a lazy line without `>` are ONE span, because marked lexes them as one paragraph; the span closes on a blank, on a quote line with nothing after the prefix, on a list item or heading inside the quote, and on a deeper quote, and a quote line after a plain paragraph line opens a new span; (4) a thematic break (marked's `hr`: `/^ {0,3}(?:(?:-[ \t]*){3,}|(?:_[ \t]*){3,}|(?:\*[ \t]*){3,})$/`) closes the span and belongs to none, and a setext underline (the tail of marked's `lheading`: `/^ {0,3}(?:=+|-+) *$/`, tried before the break so `---` after a paragraph line is the underline) closes it inclusively, because marked makes that paragraph a heading; (5) a fence follows marked's own `fences` rule, line by line: `/^ {0,3}(`{3,}(?=[^`]*$)\|~{3,})/`, with a closer of up to three spaces, the opener's exact run, any further `~` or backtick, then spaces only (marked's `{0,3}\1[~`]* *`). The fenced lines are skipped until a closer or the end of the text. | Tracking marked's block grammar exactly; a looser fence (`/^\s*```/`) | These are the reset points the exploration measured (real maximum: 122). The fence and quote rules were first looser than marked's and the cold review measured the cost: a one-line ```` ```x``` ```` or a four-space-indented fence blinded the scan (2.7 s, not degraded), and 20 quote lines each under the threshold were one paragraph to marked (2.4 s, not degraded). The rule is now marked's, copied from `vendor/marked.esm.js`, not invented. Every step is anchored and advances by index, so a line is scanned once (a 262000-character `>` prefix scans in under 200 ms). When a construct is not detected, the scan over-counts, which is the safe direction. Fenced code inside a list item (indented four or more spaces) is not a fence for this scan and is counted, which over-counts. |
| D17 | **The delimiters are `*` `_` `~` `[` `]`.** A run is a maximal sequence of one delimiter character inside one line. A newline ends a run. | Also counting `` ` ``, `<` or `(` | These five feed the three measured hot spots: `emStrong` uses `*`/`_`, `del` uses `~`, the `link` backtracking uses `[`/`]`, and the `inlineText` lookahead fires on mixed runs. Measured runs of backticks cost 0–4 ms and runs of `<` cost 40–148 ms at 200 KB, so neither needs counting. `(` is common in prose and would only add false positives, and `[a](` is already caught by its `[`. Escaped delimiters are counted too, which over-counts and is therefore safe. The degraded passage substitutes all five and the backslash (D19). |
| D18 | **The thresholds.** A span is degraded when `marks > 600` or `longestRun > 50` (R1). | 1000 or 1500 marks | At 1000 marks (`**a `×500) and at 1500 marks (`_a `×1500) the cost is already about 490 ms. The cost is quadratic, so extrapolating to 600 marks gives at most about 80 ms per span (`_a `: (600/1500)²×493). The real maxima are 122 marks and a run of 7, so the margins are 4.9× and 7×. |
| D19 | **How a span is degraded: substitute in place, lex the whole document once, restore.** The body is normalized exactly as marked does first (`\r\n` and `\r` to `\n`), so the pre-scan and the token offsets see the same text. If no span is degraded, the body is lexed once, as it is today. Otherwise each line of each degraded span has `*` `_` `~` `[` `]` and `\` replaced one for one by six distinct private-use characters (U+E000 upward, skipping any the document already contains), keeping the line's own quote prefix and list bullet, and the whole document is lexed ONCE. The placeholders are plain text to marked, so the passage is linear; every neighbour (a reference definition a link elsewhere uses, the other items of a list that holds the passage) is tokenized in its own context. After the lex every string in the token tree is walked once and the originals restored (text, code span, code, link text and href, image alt, raw), before `safeHref` and the node builders run, so no placeholder reaches the tree. If the document uses all of U+E000 to U+F8FF the passage is shown as written: the notice, then one literal block. The notice is a `{t:'degraded', notice}` block (N = `marks`, R5) emitted immediately before the top-level block that holds the passage. The block is found by source offset: the substituted offset of the passage's first line against the running sum of the top-level tokens' `raw` lengths. Substitution keeps the length, so this is the same sum as the source's, which equals the text length for every file under `openspec`, `brain` and `docs` (1394 files, 0 mismatches). A token stream whose `raw` does not add up (a test seam) puts all notices first. Adjacent text nodes of one inline run (escape tokens, inline html shown as text, text) are merged into one node, so the page never carries a node per mark. Any throw still makes the whole document one code block with D4's notice. | Lexing the text between degraded passages in pieces (the first version); backslash-escaping the passage (the second version); one notice at the top of the document | The pieces broke what a split cuts: a reference definition after the passage stopped resolving its link, and a list holding the passage became two lists (cold review round 1, cold-2). Backslash escaping fixed that and then failed round 2 (cold-3): a backslash escape is context-sensitive in CommonMark, literal inside a code span and an autolink, so `x_y` there showed as `x\_y` and an autolink's text and href carried backslashes. A placeholder has no context: it is the same plain character everywhere and is undone by one walk. A notice before the containing block is the least invasive placement that keeps each degradation visible where it happens (AC1.2) without changing the tree's block grammar. Measured with marked: a substituted 200 KB `*` run goes through substitute, lex and restore in 74 ms, and every class stays linear. The bracket cost of the previous version is gone: marked's bounded `reflinkSearch` costs about 5 µs per `[` it sees, and it now sees none, so a 262144-byte run of `[` takes 113 ms (1.3 s before) and one of 524000 bytes 183 ms. A line that is only delimiters is marked's thematic break, not a passage (D16), so a hazard needs a non-delimiter character. |
| D20 | **The worker is `lib/markdown-worker.mjs`.** It imports only `./markdown.mjs`, so the pre-scan also runs inside the worker. It exports a pure `reply({id, text}) → {id, ok:true, tree} \| {id, ok:false, error}`. It binds `globalThis.onmessage = (e) => globalThis.postMessage(reply(e.data))` only when `typeof globalThis.postMessage === 'function' && typeof globalThis.document === 'undefined'`, which is true only in a worker. | Importing marked directly | `LIB_MODULE_RE` (`server.mjs:56`, `^\/lib\/([a-z][a-z0-9-]*)\.mjs$`) already serves `/lib/markdown-worker.mjs`, so `server.mjs` needs no route. `markdown.mjs`'s `../vendor/marked.esm.js` resolves from `/lib/` to the allow-listed `/vendor/marked.esm.js` (`server.mjs:54`). The `./`-only rule (`lib/source-guard.test.mjs:43`) holds, and so does the ban on `import.meta`/`process` (`:78-84`). |
| D21 | **The budget lives in a pure module, `lib/render-budget.mjs`.** It exports `RENDER_BUDGET_MS = 1500`, `TIMEOUT_NOTICE`, `FAILED_NOTICE`, `UNAVAILABLE_NOTICE` and `renderOffThread(text, {spawn, setTimer, clearTimer, budgetMs})`, which returns `{promise, cancel}`. The promise never rejects. The timer starts **before** `spawn()`, so the budget includes worker startup. That is deliberate: the guarantee is about main-thread time, and worker startup runs off the main thread anyway, so the budget is a ceiling on how long the reader waits for the page to answer, not a measure of tokenizer cost. A cold start that times out is not final: a collapse and re-expand retries it (D25). The `timeout` outcome carries `budgetMs`, and `timeoutNotice(budgetMs)` builds the notice from the budget actually enforced; `TIMEOUT_NOTICE` is `timeoutNotice(RENDER_BUDGET_MS)`, so the default wording stays the R2 string for 1500. Every terminal path, whether a result, the timeout, an `error` event or `cancel`, clears the timer and calls `terminate()` exactly once. A late message or a mismatched `id` is ignored. | Timer logic inline in `app.js` | The fake DOM has no `Worker`. With injected effects, every race can be tested in node without the page. |
| D22 | **One worker per request (R6).** It is created on expand and terminated on result, timeout, collapse, or issue change. | A pooled worker | R6 prefers per-request. A slow document then cannot affect another row. Startup is inside the budget, so the guarantee holds whatever startup costs. **Measured by the orchestrator (2026-10-01): 39–47 ms** to spawn, import markdown.mjs and the vendored marked, and return a first render. The worker test still records startup with `t.diagnostic`, so a regression is visible. |

If `Worker` is undefined or the constructor throws, the outcome is `unavailable`. The timer arguments are `(fn, ms) => setTimeout(fn, ms)`, looked up when called. | A main-thread `markdownTree` fallback | A main-thread fallback would reopen the freeze. | D24 | **Render states.** While a render is pending, the section has `aria-busy="true"` and holds `p.note.doc-loading[role=status]` reading "rendering the document…". `timeout` renders `p.note` with `this document was too slow to render (over N ms) and is shown as plain text` (R2), N being the budget enforced (1500 by default), then `pre.md-plain` with `textContent = doc.text`. `failed` and `unavailable` use the same layout with their own notices: "this document could not be rendered and is shown as plain text" and "this browser cannot render this document off the page, so it is shown as plain text". A `degraded` block renders as `p.note` (its notice) followed by `p.md-literal`. | | Every degraded outcome is announced (AC1.2), and only `textContent` is used. |
| D25 | **Stale drop and cache.** Each control owns `seq = requestSequence()` (`lib/frames.mjs:121`). Opening takes `token = seq.next()`, and collapsing calls `seq.next()`. ## Interfaces

```js
renderOffThread(text, { spawn, setTimer, clearTimer, budgetMs = RENDER_BUDGET_MS })
  -> { promise: Promise<{kind:'tree', tree}|{kind:'timeout'|'failed'|'unavailable'|'cancelled'}>, cancel() }
// worker message protocol: in {id, text}; out {id, ok:true, tree} | {id, ok:false, error:string}
// tree Block += {t:'degraded', notice:string, text:string}
```

## Risks

- **The pre-scan bounds each span, not the document.** Many spans just under the threshold add up: 150 spans at about 80 ms each is roughly 12 s. The worker budget catches this case, and the whole document then degrades to plain text. That is R1's accepted backstop, but it is the B-only outcome for that input.
- **Worker startup** is about 40 ms (D22, measured in node as a proxy). A browser module worker may differ, but the budget timer starts before `spawn()`, so the guarantee holds either way.
- **The 122 / 7 maxima were measured with a delimiter set and reset rules that may differ slightly from D16/D17.** The AC1.4 test is the arbiter. If it fails, adjust the rules, not the thresholds.
- **Fence over-detection** (D16) and **marked upgrades** can let an expensive span through the pre-scan. The worker is the guarantee.
- **The timing assertions.** The pre-scan cases are bounded by `PRESCAN_BOUND_MS = 750`, half the worker budget. Since cold-2 lexes the substituted document once, a 200 KB hazard costs about 100 ms locally and about 230 ms on a CI runner. The first bound, 200 ms, assumed the degraded passage was never lexed and failed in CI at 204 and 232 ms. 750 ms keeps about 3x CI headroom and stays 15x under the 11 s freeze. The 262000-character quote-prefix scan keeps its 200 ms bound, because it is a pure scan with no lex. The worker test keeps budget + 300 ms.
- **Placeholder collisions** (D19): the placeholders are chosen among private-use characters the document does not contain, so restoring cannot touch the author's own; a document using the whole block is shown as written. Real artifacts never degrade.
- **This design exceeds the skill's 800-word budget,** because the brief asked for nine evidenced sections.
