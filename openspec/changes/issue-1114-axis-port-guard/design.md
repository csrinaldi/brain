# Design — #1114 S1

- Placement: `brain/scripts/axes/axis-port.guard.test.mjs` and `axis-port.allowlist.mjs`, beside `axes/layout.test.mjs` (the #1141 tree guard). It runs in `npm test`, so it gates CI with no new wiring.
- Method follows `test-spawn-hygiene.test.mjs`: mask first, match after. The literal is masked too, so each rule finds its CODE half in the masked text and reads the LITERAL half from the original at the same offset.
- Masker limits: `maskNonCode` ends a template at its first unescaped backtick, so a template nested in `${}` desyncs it (3 files today). Detection is a bracket-balance check; the fallback `maskNonCodeNested` is local to the guard and keeps `${}` content visible. Not detected: values hidden behind a variable, and literal-array membership.
- Axis values: union of adapter directory names, minus `plain` (it collides with non-axis meanings such as output format).
- Allowlist per file + rule with a frozen `max`, so debt can only shrink. Spawn rules are split by tool because the owners differ (day-start calls gentle-ai and engram).
- Population: measured from the guard's own output (`AXIS_PORT_DUMP`), reasons written per entry.
- Scope calls: provider branching in `vcs/substrate.mjs` and `vcs/lib/normalize.mjs` counts as debt (#1107): the adapter directory is `axes/vcs/adapters/`, and `vcs/` is outside it. `vcs/ci-context.mjs` is `legitimate` (the ADR-0016 seam). Resolver modules produce no hits, so they need no exclusion.
- Known gaps in S1 (not detectable by these rules): `session-start.mjs` calling the engram-only `import` op through a caller-picked allowlist, and `config.platform` being read but undeclared. S3 and #1115 own those.

# Design — S2 onward: ADR-0038 (maintainer rulings, 2026-10-02)

The target shape and the slice order are fixed by `brain-drafts/adr-0038-one-config-shape-per-axis-default-and-providers.md`. Summary for this change:
- Four axes, `vcs`, `memory`, `platform` and `sdd`, each `{ default, providers: { <name>: { version, … } }, …axis config }` in `brain.config.json`. `default` must be a key of `providers`.
- One `resolveAxis` over `lib/axis-selector.mjs`: process env > `.env` > `<axis>.default` > undeclared, except VCS, which has no `.env` level (process env > `vcs.default` > undeclared; ADR-0038 §2). Every axis refuses when undeclared, so the `claude` and `gentle-ai` code defaults go away. The refusal names `npm run brain:config -- set <axis>.default <name>`.
- `sdd.roles.<stage>` = `{ agent: "<sdd provider>:<role>", engine: "<platform provider>", model }`, cascading to `sdd.default`'s role, `platform.default` and the engine's own model. #1132 implements the `sdd.configs` + `sdd.map` reshape.
- Slice order changes: **S3 before S2.** S3 writes each existing consumer's effective value into the new keys (ADR-0026 Am8 pattern, with read-only aliases for one minor). S2's refusal then fires only where nothing was ever chosen.
- S5 is no longer "ADR-0024 Amendment 3" (that number is taken by #1165). It is ADR-0038 plus the amendments it names to ADR-0004, ADR-0008, ADR-0023, ADR-0024 and ADR-0033, each drafted separately and promoted after ADR-0038.

# Design — S3.2: the axis-shape migration (1.11.1)

- **Entry.** `brain/core/config-migrations.mjs`, version `1.11.1` (smallest above the shipped 1.11.0, the 1.9.1 precedent), a `migrate` function. It is dormant until `package.json` is cut to >= 1.11.1.
- **Context.** `migrateConfig(config, migrations, target, axisContext)` hands the entry `helpers.axisContext` and a `helpers.notice(line)` collector, and returns `notices`. The effective `platform` and `sdd` values live in env and `.env`, so `lib/axis-migration-context.mjs` walks the same chain as `resolvePlatform`/`resolveEngine` (parity table in its test) and reports the source of the winner. `.env` is read through `resolveEnv`, never edited. `brain-upgrade` and `brain:config` build the context. With no context the entry changes nothing. S3.2 left `buildDefaultConfig` untouched, so a fresh config stayed in the legacy shape; S3.3 changes `buildDefaultConfig` to pass a fresh-install context, so the same entry shapes a fresh config (its schemaVersion is stamped 1.11.1, so it is never migrated later).
- **Rules.** memory and vcs: legacy value becomes `default` + `providers.<v>: {}`; undeclared stays `default: ""`. platform and sdd: the effective value. `sdd.providers.brain = { version: "self" }` always. A custom `sdd.map` stage adds its engine to `platform.providers`; `cold-review` also gets `sdd.roles['cold-review']`. A lifecycle stage's framework never reaches `platform.providers`. `sdd.map` and `sdd.configs` are not reshaped (#1132). No `version` is written except `brain`'s. Already-shaped axes are never touched, so it is idempotent. Nothing here calls `validateAxisConfig`; the tests do, on fixtures.
- **Legacy keys: KEPT** (`memory.backend`, `vcs.provider`, `engine`, `harness`). `readAxis` already prefers the shape. After S3.3 the readers that still touch a legacy key, and so block removing it, are: `install-tools.sh`'s no-node branch (a sed text match on `vcs.provider`, because without node `config/cli.mjs default vcs` cannot run); `agent-runtime.mjs` `platformConfig` (reads `harness`; it also drops a flat `platform` today; S2 owns it); and the two writers that keep the legacy key in step during the window: `planConfigWrite` (`set memory.default` / `set vcs.default` also write `memory.backend` / `vcs.provider`) and the `brain-config.mjs` scaffold (writes `vcs.provider` beside `vcs.default`). Routed through the shape in S3.3: `install-tools.sh` (node branch, via `config/cli.mjs default vcs`), `bootstrap.sh` (identity read via `readAxis`; the VCS override and the memory prompt write through `brain:config set <axis>.default`), and the scaffold's fresh config (shape on all four axes). The one key that cannot stay is the flat `platform` string: it is the same key as the new `platform` object, so `platform` and `sdd` get no legacy mirror at all.
- **S3.3 `env:init` declares, never writes `.env`.** `bootstrap.sh` section 6 resolves `AGENT_PLATFORM` and `SDD_ENGINE` with the unchanged precedence (process env, `.env`, then the config's declared default read through `config/cli.mjs default`, i.e. the shape else the legacy keys, then the legacy `SDD_HARNESS`, then `claude` / `gentle-ai`). It declares with `brain:config set <axis>.default` ONLY a value that comes from today's default and only when the config declares none. A value that exists only in `.env`, the process env or `SDD_HARNESS` is never written to tracked config: `env:init` warns (`envOnly`, naming the `brain:config set` command) and adds a MISSING_OPTIONAL entry, as the memory prompt does; the sanctioned promotion of a per-machine value is the 1.11.1 migration with its printed source (ADR-0038 section 7). A legacy-keyed config counts as a declaration and is not re-declared. `SDD_HARNESS` feeds sdd only when it names an engine. A fresh install: the scaffold writes the shape on every axis (vcs derived from the origin, the rest undeclared, the `brain` SDD provider declared, produced by the same 1.11.1 entry with a fresh-install context), then `env:init` declares platform and sdd, and the memory prompt declares memory, so every axis ends declared and the S2 refusal cannot fire on a fresh install. Memory stays undeclared when there is no TTY and no prior answer (ADR-0004 Amendment 3: never guessed).
- **S3.3 `brain:config`.** `<axis>.default` is settable on all four axes without a migration declaring it, `<axis>.providers.<name>` is an open family, and `set <axis>.default <name>` declares `providers.<name>` as `{}` when absent (ratified point 2), validated at write time against the closed set (`MEMORY_BACKENDS`, `AGENT_PLATFORMS`, `SDD_ENGINES`, `github|gitlab`). New op `default <axis>` prints the effective default (shape, else legacy; an empty line when undeclared) for shell callers.
- **Two supporting changes the kept keys forced.** (1) `readAxis`: a shape whose `default` is `""` no longer shadows a non-empty legacy value, so an undeclared migrated axis still honours a later `brain:config set memory.backend x`. (2) `planConfigWrite`: on an axis that already has the shape, writing `memory.backend` or `vcs.provider` also moves `<axis>.default` and declares the provider, so the fix every refusal names stays effective. S2 retires both with the legacy keys.
- **Not done here.** The detected-version hint of ratified point 3 needs per-adapter version probes, which do not exist yet. `brain:config` known paths (`<axis>.default`) are S2's `brain:config -- set` work.
