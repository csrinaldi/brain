# Spec — #1251 ticket hierarchy (stated for context; this change carries only the ADR-0039 draft)

The requirements below restate the decisions in
`brain-drafts/adr-0039-a-declared-ticket-hierarchy-one-resolver-and-integration-opened-by-ticket-start.md`.
They are implemented in the slices listed in `proposal.md`, after the ADR is promoted. Anything the
ADR lists as an open question is not a requirement here. Rulings Q1-Q12, Q1-hotfix, C1-C10,
N1-N5, M1-M4 and R1 (2026-10-07) are folded in.

- REQ-1 `vcs.hierarchy.levels` is an ordered list whose order is the nesting. A parent is a higher level; skipping a level is allowed; an inversion in issue data is reported as a top-level divergence.
- REQ-2 A level declares `label`, `native`, or both; a level entry with a `parent` key, a level that declares neither, or a `branch` pattern starting with `memory` or `auto-archive` is refused (Q9, 2026-10-07).
- REQ-3 A declared `vcs.hierarchy` must carry `default`, naming a level in `levels`; resolving to it is not drift (Q7, 2026-10-07). With no `vcs.hierarchy`, brain keeps today's implicit epic/ticket model and writes no migration: hand-made `feature/…` trackers, `{type}/issue-…` branches, one hop; the close workflow and the children region still apply (C4, N1, 2026-10-07). `vcs.hierarchy` is team-layer only and changes pass `team-config-reviewed` (ADR-0040).
- REQ-4 Level labels are `level:<name>`; `type:*` is never read as a level.
- REQ-5 `lib/ticket-hierarchy.mjs` is the one resolver. It returns `{ issues: Map<number, { level, levelSource, parent, children, tracker, milestone, state, divergences[] }>, divergences: [...] }`. Level precedence is block > label > default; native data never supplies a level and a native disagreement is a reported divergence, so no background load changes a level (Q2, C1, 2026-10-07). `state` is `'open' | 'closed' | null`; `milestone` is `object | 'none' | null`: the nearest `kind: milestone` ancestor with the mirror nested as `native: object | 'none' | null` and the due date from the mirror, `null` meaning unreadable and never shown as "no milestone" (Q8, C7, 2026-10-07). An unloaded parent is a divergence only when its `forgeLoad` lane is `complete`.
- REQ-6 A milestone is an issue with `kind: milestone`; its children declare `parent:`. The native milestone object is a mirror brain creates and assigns, read for drift only (Q4, 2026-10-07).
- REQ-7 Native containment (GitHub sub-issues, GitLab epics/work items, native milestone) is read in a cached background lane for drift only, never to resolve a parent or a level; an unsupported provider or tier is unmeasured, never "no children" (Q11, C1, 2026-10-07).
- REQ-8 `brain:ticket:move` rewrites the block, the labels, the native milestone mirror and the branch together, and refuses to rename a branch while a PR is open on it.
- REQ-9 A drift check reports every issue whose sources disagree, from the resolver's divergences alone, and counts open branches and PRs on the legacy grammars, `{type}/issue-…` and `feature/…` trackers, in a repository that declared a hierarchy (Q6, C9, N2, 2026-10-07).
- REQ-10 `brain:ticket:start` resolves the nearest integrating ancestor; when trackers are missing it prints the whole chain and, after one confirmation, creates every missing tracker and draft PR top-down and writes `tracker:` into each block (Q1, 2026-10-07). A milestone integrates into `main` and an epic into its milestone's tracker (Q5, 2026-10-07). An issue with no parent starts from `main`.
- REQ-11 A hotfix is an issue labelled `hotfix` that declares no parent (prose mention only, never `parent:` or `Parent: #N`); plain `ticket:start` starts it from `main`, with no new flag and `--off-tracker` unchanged; `base-branch` needs no exemption; it is not counted in the epic's rollup. After it merges, brain proposes one "merge main into tracker" PR per open tracker behind `main`, merged with `--merge` (Q1-hotfix, C2, C3, 2026-10-07). Hotfix is not a level.
- REQ-12 When a node's integration PR merges into its parent's target (a tracker or `main`), a forge CI workflow closes that node's issue at every level, deletes a merged epic or milestone tracker, and closes the native milestone mirror when the milestone merges into `main`. It runs as the automation identity at every tier (`GITHUB_TOKEN` with `issues: write`; a project access token on GitLab). `day:start` lists PRs merged into a tracker whose issue is still open. Every PR keeps `Closes #<own issue>`, with `Part of #<parent>` added on a PR into a tracker; on a tracker merge the workflow reads the keyword to know what to close, and executes it only when the resolver places N under the node whose tracker is the PR's base; any other keyword is reported, never executed; `issue-link` is unchanged (C5, N3, M2, 2026-10-07). The same step rewrites the parent's children region (N5). A node whose integration PR merged before it was Ready to close is not closed and its tracker is not deleted; it is reported as merged but open (N4). When a child integrates into a merged-but-open node's live tracker, the workflow reports the node and `day:start` proposes a new draft integration PR for the remainder (head the tracker, base the same target, `Closes #<node>`) under the user's credentials, creating it only after the human confirms (Tier 2) and only reporting in a non-interactive run (R1, 2026-10-07); it is marked ready at Ready to close; its merge closes the node and deletes the tracker. If the last child closes while the tracker has no commits its target lacks, brain closes the node and deletes the tracker directly (M3, 2026-10-07). The workflow runs in every project (N1).
- REQ-13 The C5 workflow marks a draft integration PR ready when every child of its node is closed; the merge follows the declared ADR-0037 autonomy mode and no agent merges (Q10, C10, 2026-10-07).
- REQ-14 Branches are hierarchical, with a fixed `tracker` leaf for integrating nodes and no type prefix; a segment comes from the issue number, never a name (`release-1300/tracker`), so it is never renamed; a level without `branch` contributes no segment; in a repository that declared a hierarchy, the legacy grammars are parsed while any open branch or PR there uses them; in a repository without one they are the grammar and are never removed (Q5, Q6, C6, C9, N2, 2026-10-07). Lane branches keep their names.
- REQ-15 The parent's body carries a generated children region between HTML markers outside any `brain-graph/1` fence, marked "generated by brain, not read, do not edit". It replaces the repo-wide `epic:map` region in epic bodies and is written by `replaceMapRegion` under its outside-bytes proof, by the close workflow in the step that closes an issue and by `day:start` as the safety net, a Tier 1 write for an agent (N5, M4); every project gets it (N1); the repo-wide graph is printed only (`epic:map --dry-run`) and in the UI; #1335 writes only the block. No brain tool reads the region's contents, pinned by a test (Q12, C8, 2026-10-07).
- REQ-16 `issueList` returns `state` and `body` on every entry, additively, on both providers (shipped in #1257).
- REQ-17 A new gate, `integration-ready`, refuses to merge an integration PR (head = the `tracker:` its issue's block declares) while any child of its node is open or unknown, judged through the resolver by content, never by branch name; it runs in every project; where `vcs.hierarchy` is declared it is detection at `lite` and required at `standard` and `regulated`, and on the implicit model it is detection-only at every tier; no label bypasses it (N4, M1, 2026-10-07).
